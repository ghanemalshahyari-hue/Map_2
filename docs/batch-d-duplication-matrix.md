## Locked takeaways this matrix confirms

1. **One canonical lifecycle store** — `scenario_lifecycle` + the new `scenario_revisions` table, both owned by `scenario-approval-store.js`/`scenario-revisions-store.js`. No parallel scenario manager was introduced anywhere in D1–D6.
2. **Deterministic canonical-content hashing** — reuses `sim/journal.js`'s `stableStringify`/`hashState` (recursive key-sorted JSON → sha256), already key-order-independent. Verified in `test-scenario-revisions-slice1.js` Part 1 §2 ("same content, different key order → same hash").
3. **The real, pre-existing duplication in this app was the two scenario pickers**, not a proliferation of storage backends. Fixing that (D6) mattered more than inventing new infrastructure.
4. **Two genuine gaps found and fixed as real defects, not just documented**: the missing self-approval-denial check (D2), and the total absence of content-aware revisioning (D1) underneath an otherwise-correct blunt invalidation rule.
